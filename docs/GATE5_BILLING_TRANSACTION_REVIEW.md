# Transaction review — not deployed
The draft RPC atomically records a unique invoice, updates paid coverage, marks the founding slot paid and records the event. Row locking and optimistic version fencing reject stale reconciliation; the backend must read the version before fetching Stripe state. Only service_role may execute. Initial customer/subscription binding is still required. All other future writers must increment the version. The 12-invoice guard limits local activation, NOT Stripe charging; a Stripe-side schedule or cancellation before the 13th invoice is mandatory before checkout is exposed. Duplicate invoice events do not reactivate access. Refunds, disputes, failed payments and cancellation require separate fenced reconciliation. SQL has not been run. Do not deploy to production.
Staging verification: two concurrent requests for same invoice; duplicate event; mismatched customer; stale version; rollback on unique violation; anonymous and authenticated RPC denial; 13th invoice rejection; no paid access after cancellation replay. Use synthetic data only.
