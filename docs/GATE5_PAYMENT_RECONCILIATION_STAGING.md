# Payment reconciliation — isolated draft
Added pure validator for settled full-price monthly invoices with matching customer/subscription, test mode, fixed price and bounded coverage. It assumes legacy normalized Stripe invoice fields; fetch adapter must pin and verify API version and normalize fields. Do not pass webhook payload or client data directly. No entitlement mutation or endpoint is enabled.
Remaining: persistent customer/session binding, verify invoice line from fetched invoice (not independent input), validate actual settlement and refunds/disputes, support taxes and payment failures, atomic event ledger + account update with concurrency fencing, initial subscription binding from verified checkout, cancellation and renewal policy, 12-month limit. Current validator intentionally rejects unsupported invoice structures. No live use. Tests require execution; staging database not changed.
